FIELD GUIDE 01 / Build the basics

Turn a CSV into a readable data page

Handle quoted fields, empty cells, and meaningful headers before you turn rows into a trustworthy interface.

NOWOI / FIELD NOTES8 min readFirst edition 2026.11.08

Try it in the workshop ↗

A community organizer sends you workshop availability for a small website. Three sessions sound straightforward, until one name contains a comma, one note spans two lines, and an empty seat count means something different from zero. Build around those distinctions before choosing a table style.

What you will take away

  • Quoted commas and line endings belong to fields; line splitting is not CSV parsing.
  • Preserve empty values and zero, validate record width, then format for readers.
  • Use meaningful table headers and textContent, with repairable error messages.
01

01 / Agree on what each column means

The page should answer three questions: what is the session, where is it, and are places available? Keep four columns: session, room, seats, and note. Use this fictional fixture. It contains one header record and three data records, including two empty cells at the end.

session,room,seats,note
"Maps, without jargon",A,12,"Bring a laptop"
"Design ""office hours""",B,0,"Waitlist
opens Monday"
"Open studio",C,,

The doubled quotes represent one literal quotation mark. Zero means the session is full; an empty seat count means the organizer has not supplied it. Preserve that distinction instead of using a truthiness fallback that replaces zero. Translate internal field names into useful column labels. Do not invent a source or update date to make the page look authoritative.

02

02 / Parse records, not separate lines

Splitting on newlines and then commas breaks this fixture twice: it divides a session name and turns part of a note into another record. A small parser needs state: whether a quoted field is open and whether its closing quote has been reached.

  1. Outside quotes, a comma finishes a field and a line ending finishes a record.
  2. Inside quotes, commas and line endings are content. Two consecutive quotes contribute one literal quote.
  3. After a closing quote, accept a delimiter or record ending. Reject unexpected characters rather than guessing.
  4. At the end, preserve the final field, including an empty field after a trailing comma. An unclosed quoted field must produce an error.

Accept ordinary LF and CRLF record endings without stripping meaningful field whitespace. Paste the fixture into the data lab and check for three records with four cells each. Remove the note's closing quote and expect an explicit parsing error. A maintained parser library is a reasonable production choice; keep these fixtures whichever implementation you choose.

03

03 / Give the result table semantics

After parsing, compare every record's width with the header. Report a short or extra record instead of pushing overflow into the final cell. A record number may differ from a physical line number because quoted fields can span lines.

Use a table with separate header and body sections. Mark column headings with th scope="col"; use ordinary data cells for values. Provide a table title and explain any display conventions. Bold styling alone cannot establish the relationships that assistive technology needs.

const cell = document.createElement('td');
cell.textContent = rawValue;
row.append(cell);

On a narrow screen, allow the table region to scroll without widening the entire page. Preserve complete session names and meaningful note breaks. Display an empty value as “Not supplied” if helpful, but leave the underlying value empty. Formatting should explain the data, not quietly rewrite it.

04

04 / Keep input as text

Replace a session name with <img src=x onerror=alert(1)>. The expected preview displays those exact characters in a cell. It must not create an image or execute an event. This acceptance check only requires text; there is no need to trigger a popup.

textContent inserts text. innerHTML asks the browser to parse markup. Avoid interpolating imported values into an HTML table string. If a future version supports links, validate permitted protocols and destinations separately; that does not justify treating every cell as HTML.

Use fictional data in a public demonstration. Browser-side reading does not itself prove that an entire website makes no external requests. Describe whether your actual deployment uploads, retains, or logs imported data before asking people to trust it with private records.

05

05 / State the limits of the preview

Try empty input, headers only, a missing cell, an unclosed quote, and the complete fixture. Each needs a useful response: a request for input, a no-records message, or an error identifying the structural problem. “Invalid data” is too broad to help someone repair a file.

This exercise assumes a header record and comma separators. It does not detect semicolon dialects, interpret spreadsheet formulas, or repair unknown encodings. Read a selected file with await file.text(), which decodes as UTF-8. State size, encoding, and row limits before processing. Larger datasets need bounded rendering and an honest count of visible records.

Finally, ask another person to distinguish a full session from an unknown count and choose a workshop using only the result. Successful parsing is necessary; a readable decision is the outcome you are building.
