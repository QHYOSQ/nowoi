FIELD GUIDE 01 / 构建基础

把 CSV 变成真正可读的数据页

从带逗号的名称开始，处理引号、空值与表头，让数据既读得懂，也不会变成可执行页面。

社区工作坊的负责人发来一份报名表，希望你把剩余名额放到网页上。三个活动，看起来只要把逗号换成表格线。但名称里也有逗号，备注占了两行，零个名额与尚未填写不能混为一谈。先把这些小边界说明白，才能做出值得相信的数据页。

读完，你会得到

  • 引号中的逗号和换行属于字段，不能用按行切分代替 CSV 解析。
  • 保留空字符串与零值的区别，先验证结构，再格式化显示。
  • 用表头语义和 textContent 呈现结果，并把格式错误说清楚。
01

01 / 先约定每一列代表什么

这次页面只回答三个问题：活动是什么、在哪里、还有多少位置。保留四列：活动名称、房间、剩余名额、备注。用下面的虚构样本试验；它有一个表头和三条记录。最后一条记录的两个空单元格必须保留下来。

session,room,seats,note
"Maps, without jargon",A,12,"Bring a laptop"
"Design ""office hours""",B,0,"Waitlist
opens Monday"
"Open studio",C,,

第二条记录的备注虽然换了行，仍然属于同一格。活动名中的两个双引号表示一个实际的双引号。剩余名额为 0 表示已经满员；空字符串表示尚未提供数字。先保留这些原始区别，再决定如何显示，别用 value || 'Unknown' 抹掉合法的零值。

把列名写给读者看：将 seats 显示为“剩余名额”，而不是默认所有人都懂内部字段。没有数据来源或更新时间时，就不要自行补上一个看似可信的日期。

02

02 / 解析记录，不是切开每一行

text.split('\n').map(line => line.split(',')) 无法处理这个样本：第一项名称会被拆成两列，多行备注会被错认成下一条记录。换一个正则表达式也不等于已经覆盖这些组合。小型解析器需要记住当前是否处于引号内，以及字段是否已经关闭。

  1. 只有引号外的逗号才结束一个字段；只有引号外的换行才结束一条记录。
  2. 引号内遇到连续两个双引号时，加入一个双引号；遇到关闭引号后，只接受分隔符或记录结束。
  3. 同时接受常见的 LF 与 CRLF 行结束。不要把引号内的换行删掉，也不要随手修剪每个字段的首尾空格。
  4. 文件结束时保存最后一个字段；结尾的逗号意味着还有一个空字段。若引号未关闭，则报告错误，别显示半张“成功”表格。

在本页的数据实验室粘贴样本，先确认得到三条数据记录、每条四列。再删掉备注的关闭引号：预期结果是清晰的解析错误，而不是一张悄悄错位的表。对上线项目，可选择支持这些边界的成熟解析库；无论选哪种实现，都保留这组验收样本。

03

03 / 用表格语义承载数据

解析成功后，再检查每条记录的列数是否与表头一致。发现三列或五列的记录时，指出第几条记录出错；不要自动把后面的内容挤到最后一列。记录编号与文件行号可能不同，因为一个字段内部可以换行。

用 table、thead 和 tbody 组织结果。第一行用 th scope="col" 标明列标题，普通值用 td。表格上方给出名称和简短说明；做完整页面时，用表格标题关联这份数据。屏幕阅读器需要的是可辨认的表头关系，视觉上的粗体不能代替这些关系。

const cell = document.createElement('td');
cell.textContent = rawValue;
row.append(cell);

手机端可以让表格区域横向滚动，但别把整张网页撑出屏幕。保留完整活动名，并给备注使用保留换行的显示方式。空值可以显示“未提供”，同时在页面说明这个约定；不要在原始数据中把空值改成零。

04

04 / 输入内容始终是文本

把第一条活动名称换成 <img src=x onerror=alert(1)>，重新生成预览。合格结果是单元格原样显示这一串字符，没有图片，也没有执行事件。这个练习只需要字符串，不需要真的触发弹窗。

原因在于 textContent 写入文本，而 innerHTML 会把字符串交给 HTML 解析器。不要用拼接的表格模板包住用户输入，也不要把“数据来自我自己的表格”当成安全边界。如果以后增加网址列，应单独校验允许的协议和链接目标，不能把所有单元格一起升级为 HTML。

本地预览只适合不含真实个人信息的练习样本。是否上传、保存或记录原始 CSV，取决于你实际部署的系统；页面承诺必须与实现一致。文件选择后在浏览器读取，并不自动代表整个网站没有外部请求。

05

05 / 给预览明确的能力范围

分别试验空输入、只有表头、缺一列、引号未关闭和完整样本。空输入应提示粘贴数据；只有表头应说明暂无记录；格式不一致应中止预览并指出问题。不要把这些状态全部写成“无效数据”。

本例约定首条记录是表头、分隔符是英文逗号，不负责识别分号文件、电子表格公式或其他字符编码。文件可以用 await file.text() 读取，这条路径按 UTF-8 解码。若支持文件导入，先展示可接受的编码、大小与行数范围。数据量增长后应限制一次渲染的数量，并告诉用户当前显示了多少条，别让一份文件冻结整个页面。

最后把结果交给另一个人：只看表格，能否区分“满员”和“未提供”，能否找到自己想参加的活动？解析正确只是开始；读者能根据结果做决定，数据页才算完成。
