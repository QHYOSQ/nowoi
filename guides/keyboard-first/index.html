FIELD GUIDE 03 / 使用体验

只用键盘，走完一张网页

从原生按钮到焦点返回，沿着一次完整任务检查每个可以操作、看见和退出的位置。

你做了一张工作室网站：顶部有导航，中间有筛选和咨询入口，底部有确认弹窗。鼠标点起来很顺，但访客用 Tab 走到筛选卡片时，焦点突然消失了。与其事后给每张卡片补键盘事件，不如从用户要走完的路线重新安排控件。

读完，你会得到

  • 导航用链接，当前页动作使用原生按钮，避免正数 tabindex 排队。
  • 焦点必须持续可见，且不能被布局遮挡或裁掉。
  • 模态对话框要管理进入、关闭与返回焦点，并用完整任务路线验收。
01

01 / 先分清链接与动作

去另一个页面或某个页面位置，用带有效 href 的链接；展开筛选、打开对话框或清空输入，用 button。在表单里的普通动作按钮，明确写 type="button"，避免意外提交。真正的提交按钮则使用 type="submit"。

<a href="/en/guides/readable-data/">Read the data guide</a>
<button type="button">Open filters</button>

原生控件已经带有角色、焦点和键盘行为。链接通常由 Enter 激活，按钮支持 Enter 与空格。给一个 div 增加点击事件，甚至加上 role="button"，都不会自动获得完整的按钮行为。只有确实需要定制控件时，才承担额外的状态与操作设计。

不要为了让整张卡片可点击，在链接里面再放按钮。将卡片标题作为明确的链接入口，其他动作独立出现。这样读者知道自己要跳转还是改变当前页面。

02

02 / 让路线跟着内容走

先安排合理的文档顺序，再用布局把它呈现出来。若视觉上从左到右的控件，在 Tab 顺序里却不断跳行，问题通常出在结构或视觉重排。不要用一串正数 tabindex 给某几个元素插队；它会让后续维护和全站导航更难预测。

从浏览器重新载入页面，把鼠标移到一边。第一次按 Tab 时，最好能看到跳到正文的入口，略过每页重复的导航。之后应按合理顺序经过导航、主要操作、表单和页脚。普通说明段落不需要为了“可访问”全部变成 Tab 停靠点。

打开本页的发布检查清单，用 Tab 找到第一项，按空格改变选中状态，再按 Shift + Tab 返回。确认操作后焦点仍然在可预期的位置。检查清单用于演练这条路线，不会因为勾完几项就替你证明网站符合某项完整标准。

03

03 / 让当前焦点持续可见

每次按 Tab，都应该看得出下一次按键会作用在哪里。保留浏览器默认轮廓，或者提供同样清晰的替代样式。仅有鼠标悬停效果不够；选中的导航项，也不是当前键盘焦点的代替品。

a:focus-visible,
button:focus-visible,
input:focus-visible,
textarea:focus-visible {
  outline: 3px solid #126b52;
  outline-offset: 4px;
}

这是一段起点样式，不是自动达标的凭证。检查轮廓在浅色、深色和图片背景上是否可辨，是否被圆角容器裁掉，以及固定导航是否盖住获得焦点的输入框。输入文字时若键盘挡住控件，也应调整滚动与布局。

焦点提示不应该几秒后淡出，也不要因为动画结束就把焦点移到页面顶部。屏幕上的当前位置，必须能跟得上用户真实的操作位置。

04

04 / 弹窗要有入口，也要能原路返回

如果你的项目真的需要模态对话框，可以优先考虑原生 dialog 与 showModal()。仅设置一个名为 dialog 的角色，并不会自动锁住背景操作或管理焦点。让对话框有清楚的标题、可见的关闭按钮和 Escape 退出方式。

打开时，把焦点放到内容上合理的位置。简短确认框可以先放在安全的取消动作上；很长的说明可能更适合先聚焦标题或开头的静态文字。Tab 与 Shift + Tab 应留在打开的模态区域内，背景暂时不可交互。

let returnTo;
openButton.addEventListener('click', () => {
  returnTo = openButton;
  dialog.showModal();
});
dialog.addEventListener('close', () => {
  if (returnTo?.isConnected) returnTo.focus();
});

原生对话框已有部分返回焦点行为；这段代码明确了本例的返回目标。关闭后通常回到打开它的按钮。若按钮已被移除，就为后续任务选择合理位置，不要把焦点丢到无法辨认的页面背景。不要在没有模态需求的区域设置键盘陷阱。

05

05 / 留下一条可重复的验收路线

  1. 从重新载入开始，只用 Tab 与 Shift + Tab 经过主要页面，记下任何看不见焦点或顺序跳跃的位置。
  2. 用 Enter 打开导航链接，用空格操作按钮和复选框，确认没有意外的页面滚动或重复提交。
  3. 填写一个表单，故意触发错误，再修正并继续。核对焦点是否落在能完成修正的位置。
  4. 若有模态对话框，试验打开、向前遍历、反向遍历、Escape 关闭，以及返回打开按钮。
  5. 在较窄窗口和放大页面后重走一次，留意被遮挡的控件与裁切的轮廓。

记录“在哪个页面、哪个控件、哪次按键后发生什么”，比写“键盘支持不好”更容易修复。键盘验收也不能代替屏幕阅读器、触屏或其他辅助技术的检查。它的作用，是让一条具体任务路线真实地走得通，并在修改界面后仍然可以重走。
