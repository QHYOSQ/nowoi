FIELD GUIDE 05 / 使用体验

“本地处理”到底能承诺什么

把工具输入、浏览器存储、网站访问和第三方请求分别说清楚，隐私说明才有可核对的边界。

有人想用在线工具整理一段尚未发布的会议记录。“在浏览器中处理”很有吸引力，却不能自动回答记录是否上传、草稿是否保存、网站是否有访问日志这三个不同的问题。设计一个值得信任的本地工具，关键是让数据实际经过的路径与页面上的承诺一致。下面讨论的是设计和验证方法，不代表每个标有“本地”的网站都已经这样实现。

读完，你会得到

  • 工具输入、网页访问和第三方服务是不同的数据路径。
  • 浏览器存储应有明确用途、主动选择与删除入口。
  • 用合成样本核查请求和存储，并记录检查边界。
  • 每次依赖变化，都要重新核对隐私承诺。
01

01 / 先画出数据边界

从一个具体操作开始：访客粘贴 MEETING-DEMO-47，点击整理，再导出结果。分别列出输入、计算结果、存储位置和网络请求。浏览器可以读取用户主动选择的文件，并在客户端完成计算；但是，能在本地计算与实际没有上传，仍是两件需要分别确认的事。

数据可能经过哪里需要说明什么
粘贴的记录、选中的文件页面内存；若程序发送，也可能到服务器工具是否上传这些内容
保存的草稿或偏好浏览器存储保存内容、触发条件与删除方法
网页访问请求托管商、CDN 等基础设施按实际配置说明访问日志
字体、统计、广告等请求对应第三方服务服务、用途与相关数据处理

“工具输入不上传”描述一条具体边界。“全站没有任何数据传输”则连下载网页本身也无法解释。网站需要通过网络提供页面，不代表工具输入一定被上传；工具输入不上传，也不代表网站完全匿名。

02

02 / 计算与保存，设计成两个选择

对于临时文本工具，一个清楚的默认方案是只在页面内存中处理输入。用户没有选择保存时，程序不应悄悄把内容写进 localStorage。这是本教程建议的产品选择，不是浏览器替你执行的默认保护。

localStorage 属于当前来源，可以跨浏览器会话保留数据，没有自动到期时间。它不是加密保险箱；同一来源执行的脚本可以访问这类存储。共享电脑上的下一位使用者也可能通过恢复页面或工具功能看到已保存内容。

若确实需要草稿功能，使用默认未选中的“在此浏览器保存草稿”，并在旁边写明保存哪些内容、存在哪里、如何删除。只有用户主动开启并点击保存时才写入；保存失败应明确提示，不能仍显示“已保存”。浏览器策略、空间限制和隐私模式都可能改变保存结果。

03

03 / 用假数据走一遍完整路径

验证时使用不含个人信息的独特样本文字，如 MEETING-DEMO-47。先打开开发工具的网络面板，再重新加载页面，这样能看到初次访问与之后操作的请求。记录域名、请求类型和发起者，然后输入样本，依次执行整理、复制、导出及任何保存操作。

  1. 检查操作前后是否出现新请求，尤其是表单、Fetch/XHR、统计或错误上报请求。
  2. 检查请求 URL、查询参数和可查看的请求正文，确认样本文字有没有被发送。
  3. 查看浏览器存储区域，比较操作前后新增的键和值。
  4. 刷新页面，确认恢复行为是否符合页面说明。

不要把敏感原文放进 URL：查询参数可能进入历史、日志或分享链接。网络检查只提供当前版本、当前环境和已执行步骤的证据；没看到样本并不能证明所有操作、未来更新或浏览器扩展都绝不会传输内容。代码审查与重复检查仍然必要。

04

04 / 导出与删除要有明确对象

导出让用户自己决定在哪里保留结果。导出文件名可以包含工具名称与日期，但不应擅自放入文档标题中的敏感信息。提示下载文件仍然存在于设备上；清空网页输入不会删除已经下载、复制或另行备份的副本。

区分“清空当前输入”与“删除此浏览器中的草稿”。前者重置界面和内存，后者还需要删除工具自己保存的键。下例仅演示删除一个明确命名的键，实际项目要按真实存储结构实现：

localStorage.removeItem("example-tool:draft");

不要随便使用 localStorage.clear()，否则可能删掉同一来源下其他功能的偏好。删除后刷新，确认草稿没有恢复；导出后打开文件，确认字符与换行正确。若程序用了临时对象 URL，完成相关下载后也应按实现释放不再需要的引用。

05

05 / 把承诺写成可以核对的句子

与“绝对安全、完全匿名”相比，下面这样的说明更容易落实：

本工具在浏览器内整理你输入的文本，不把该文本发送给我们的服务器。默认不保存草稿；只有你主动开启保存并执行保存操作后，草稿才保留在当前浏览器。网页托管和已启用的外部服务按隐私政策处理访问请求。

这是一段需要与实际实现核对后才能使用的示例。如果工具调用云端模型或远程接口，就不能照搬第一句。如果嵌入统计、广告、外部字体或错误监控，也应把这些请求单独列清楚，确认不会把输入和结果夹带进事件属性或错误信息。

页面上的“无须注册”“本地计算”“不保存草稿”分别回答不同问题，不能互相替代。对仍未核实的托管商日志保留时间，应查配置或供应商说明，不要编造“立即删除”。

06

06 / 每增加一个依赖，就重新看一次边界

一次检查不能替代以后的维护。新增广告、分析脚本、反馈表单或远程错误监控时，数据路径都可能变化。在发布记录里写明新增服务、发送的数据、触发条件以及说明页面如何更新。

下方数据练习用于把数据按处理、保存和请求分类。先写出自己的承诺，再逐项找实现证据；若一句话无法对应到代码、配置或可重复操作，就把它改得更准确。

处理高度敏感的内容时，先判断网页工具是否适合当前场景。不要为了演示本地处理，就要求用户上传真实合同、凭证或医疗记录。使用合成样本也能验证大多数格式处理与保存流程，而无需扩大验证本身造成的数据暴露。
